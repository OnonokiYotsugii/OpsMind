# ADR 0004：手写 Agent 与事务内审批凭据

状态：接受。日期：2026-09-14。

## 决策

手写有界循环，复用 P2 HTTP 客户端，增加普通 Tool Calling 模式，
不与 JSON Object 响应模式混用。工具 Schema、风险、参数校验和执行入口由代码注册，
模型仅提供调用名称和参数。

一次模型轮次只接受一个工具调用，保持消息与待审批操作简单、可解释。
暂不引入 LangGraph、多 Agent、后台任务系统或 Redis。

运行与审批状态持久化到 agent_run。审批通过后在持有该运行行锁的事务中调用
P1 的事务内部业务函数，并同事务记录动作 ID 与执行结果。相同动作的并发或重复请求
读取已有凭据，不再次执行。保存点用于业务失败时保留失败凭据而不残留部分写入。

步骤和处理预算跨人工确认保留。人工等待有独立有效期。
中断的活动运行过期后标记失败，不推测性重放操作。

## 代价与边界

同步数据库操作在短工作线程中执行；不会在模型网络等待期间持有事务。
JSON 运行日志便于学习，但不提供高级审计检索、消息加密或自动清理。
本地固定演示身份仍限制部署范围。

失败状态不保证没有副作用：某次确认已经成功写入后，模型总结仍可能失败。
API 明确提供执行凭据，用户以凭据和业务数据为准。

不同运行产生的新动作不共享去重键，这不是全局工单去重系统。
真实供应商工具联调留待用户后续测试，本阶段自动测试覆盖协议与真实数据库边界。
