# ADR 0001：渐进式单体与独立 Python 环境

状态：接受。日期：2026-09-12。

## 背景

项目同时用于学习和求职展示，需要能够解释底层机制、复现运行结果，又不能因框架和部署复杂度妨碍第一条业务链路。

## 决策

采用模块化单体、src 布局、Python 3.13、uv 和项目 .venv。提交 uv.lock 固定解析结果，以 uv sync --locked 复现环境。使用现有 Python 次版本减少环境切换；若后续必要依赖不兼容，再记录升级或降级决策。

P0 只引入配置及开发检查依赖。P1 才引入 FastAPI / SQLAlchemy / PyMySQL / Alembic；先用同步数据库访问降低事务和调试复杂度，届时配合 FastAPI 的同步路径使用。是否需要异步由实际并发需求决定。

使用标准库 logging，暂不引入日志平台。P3 手写 Agent Loop，P5 再使用 LangGraph，审批安全从第一次开放写工具开始生效。

## 代价与替代方案

uv 需要额外安装，但已在本机可用，锁文件与环境管理统一。直接使用 Anaconda 全局环境容易发生依赖串扰；仅 requirements.txt 难以同时描述开发依赖和包构建。暂不引入微服务、Redis、Docker 或通用 Repository 基类，减少需要维护而没有业务依据的抽象。
