# 学习路径与作品证据

每阶段采用“理解一个机制 → 实现最小闭环 → 故意触发失败 → 用测试解释结果”的方式。完成后先复盘，再进入下一阶段。

| 阶段 | 应能独立解释 | 保留的作品证据 |
| --- | --- | --- |
| P0 | 虚拟环境与锁文件的区别；环境变量优先级；模块分层 | 可复现命令、ADR、配置测试 |
| P1 | HTTP 校验、事务、外键和异常映射 | API 示例、迁移、真实数据库测试 |
| P2 | 结构化输出失败、超时与重试边界 | 输出模型和失败用例 |
| P3 | Tool Calling 的消息往返；模型决策与程序权限 | 多轮工具记录、审批拒绝与步数上限测试 |
| P4 | 文档切分、检索证据与诊断依据 | 固定问题集和来源引用 |
| P5 | 状态恢复、重复执行与审批绑定 | 中断恢复演示和幂等测试 |
| P6 | 指标定义、基线和回归 | 固定评估集及真实测量结果 |
| P7 | 如何从全新环境运行和演示 | 部署说明、演示视频、架构图 |

## P0 自测

1. 将日志级别改成 VERBOSE，解释为什么配置应在启动时失败。
2. 在 .env 与环境变量里设置不同级别，预测最终值，再运行验证。
3. 解释为什么 SecretStr 不等于日志自动脱敏。
4. 画出“用户查询设备”和“Agent 建议创建工单”的调用路径，指出事务与审批应在哪里。
5. 解释为何维修记录关联员工 ID，以及为何禁止级联删除设备历史。

## 简历记录原则

每阶段记录“解决的问题、个人实现、验证证据、边界与取舍”。P0 只能描述工程初始化和架构设计，不宣称已实现智能诊断。后续成功率、延迟和准确率必须来自固定数据集的实测，同时保留样本数、模型版本与测试条件；不编造提升比例。

最终作品优先展示一条可信的闭环：故障输入 → 数据与知识检索 → 有依据的建议 → 人工确认 → 工单落库 → 可追踪和可评估。
